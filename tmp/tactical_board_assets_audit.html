Auditoría de assets de la Pizarra / Editor táctico actual

Inventario específico de los recursos gráficos que consume hoy la pizarra de tareas: mezcla de Fabric.js + dibujo procedural, emojis, texturas/campos/estadios, sprites de tokens, logos y modelos 3D. Este documento no copia ni modifica assets: solo audita qué existe, cómo se pinta y si conviene reutilizarlo.

2. Diagnóstico del sistema actual

  • Jugadores/porteros/fichas: se pintan sobre Fabric como grupos, camisetas SVG embebidas y, en ciertos casos, sprites PNG o recortes fotográficos.
  • Balón, conos, picas, porterías, flechas, líneas, zonas: en su mayoría se dibujan de forma procedural con fabric.Rect, fabric.Circle, fabric.Line, fabric.Path, fabric.Triangle y fabric.Group.
  • Emojis: se insertan como fabric.Text usando Unicode, no como imagen.
  • Campo 2D/2.5D: se genera como SVG y se enriquece con tiles y overlays de estadio.
  • Campo/estadio 3D: se apoya en Three.js + GLTF/OBJ + texturas físicas.

3. Criterio recomendado

  • Reutilizar: texturas de césped, overlays/top views de estadio, logos/vallas, goal model 3D, token sprites premium, avatars y recortes si se quiere una family “photo/cutout”.
  • Crear desde cero: flechas, líneas, zonas, conos/picas/material premium 2D, porterías 2D premium, family de balones 2D premium.
  • Descartar: campos legacy genéricos que no siguen el lenguaje visual actual.
  • Enlazar: materiales PBR/ambientCG y modelos 3D auxiliares como recursos de pipeline, no como assets UI finales.
